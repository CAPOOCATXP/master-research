# 研究计划书 / Research Proposal

**题目：记忆库压缩何时改变工业报警——面向边缘部署的决策保持筛选方法**

**英文题目：When Does Memory Compression Change Industrial Alarms? —— Decision-Preserving Screening for Edge Anomaly Detection**

**申请人：** 吴源泰（Wu Yuantai）　**日期：** 2026 年 11 月　**周期：** 10 周

---

## 摘要 Abstract

工业视觉异常检测常采用「正常样本记忆库 + 最近邻检索」的做法：把训练时见过的所有正常图像块存成向量库，新图片的每个块去库里找最近邻，距离越远越异常。这套做法精度高，但记忆库很大，边缘设备存不下、也算不快，所以通常会被压缩。

问题在于：**压缩以后，同一张图在同一个阈值下的报警决定，可能悄悄变了。** 而 AUROC 这类排序指标看不出来，因为它对分数的单调变换不敏感。真正影响产线的不是排序，而是「阈值这一刀切在哪、切得准不准」。

本项目要回答一个具体问题：**在编码器、预处理、记忆库版本和阈值全部冻结的前提下，压缩会不会改变二元报警决定？如果会，能不能用区间把「确定正常」「确定报警」和「必须查完整库」分开，并且不把「不知道」当成「正常」？**

方法上不发明新的数学。我们沿用三角不等式这一既有工具：边缘侧只保存少量**观测中心**及其**覆盖半径**，为每个查询算出真实分数的一个区间 `[L, U]`。区间完全落在阈值一侧就本地判决；跨过阈值就升级查完整库；库不可用或版本不匹配就返回「未解决」。核心承诺是**决策保持**，不是更高的准确率——被忠实保留的误报仍然是误报，这一点必须讲清楚。

评价在公开工业数据集上进行，测量决策不一致率、真实召回与误报、区间宽度、字节数和端到端延迟，并给出配对的置信区间。**预期成果不是「我们的方法更好」，而是一条可复现的边界：压缩到多少、在什么条件下，报警还能保持；什么时候不能。**

## 1. 研究背景 Introduction

### 1.1 背景

工业质检的难点很朴素：**好的产品长得都差不多，坏的样子却千奇百怪。** 你没法事先把所有缺陷类型都收集齐，所以通常反过来做——只学「正常长什么样」，跟正常差得多的就算异常。这类方法叫单类（one-class）或无监督异常检测。

近年表现最好的一类做法是**基于记忆库的检索**。它把训练集里所有正常图像的局部块（patch）提成特征向量存起来，测试时逐块算最近邻距离，取最大值作为图像分数。PatchCore [1] 是这个方向的代表作，它用贪心 coreset 把记忆库压到 1%–25%，精度几乎不掉。AnomalyDINO [2] 进一步证明，冻结的 DINOv2 特征加上少量参考图就能做得很好，完全不需要训练。

但这里有个工程上的硬约束：**记忆库的大小随训练数据线性增长。** 一个 200 张图的类别，按每张 676 个块算，库里有十几万个 1536 维向量，几百兆。放在边缘盒子上就很紧张了。于是压缩几乎是必然的选择。

### 1.2 问题

压缩带来一个容易被忽略的后果。

记忆库变小以后，每个测试块的最近邻距离通常会变**大**（因为候选点变少了）。这是单调的变化，看起来无害。但图像分数是「所有块取最大」，这是一个**非线性**的聚合；再加上不同图像的分数分布形状不同，压缩对分数的影响**不是整体平移**，而是有选择地改变了一部分图像的位置。

结果就是：**原来刚好在阈值下面一点的图，压缩后可能翻到上面去，变成一次新的误报；反过来也可能漏掉。**

这一类变化，AUROC 完全看不见。原因很简单：AUROC 是对所有阈值积分的排序指标，而产线只用**一个**阈值。两个 AUROC 完全相同的模型，在 1% 误报率这一点的表现可以差很多。MSC-AD [7] 这样的工业数据集也说明了同一件事：工业场景真正关心的是低误报率下的表现。

所以本项目把问题收窄成一句话：

> **在检测器完全冻结的前提下，记忆库压缩会不会改变固定阈值下的二元报警决定？如果会，能不能用可审计的区间把这件事管住？**

### 1.3 研究假设

我们提出两个可以被否证的假设：

- **H1（缺口假设）**：在有用的存储降幅下（比如压到 10%），压缩会带来**不可忽略**的报警不一致，即在至少两个类别上达到 2 个百分点以上。
- **H2（机制假设）**：用观测中心和覆盖半径构造的保守区间，能在**不改变任何判决**的前提下，让相当一部分图像（目标 20% 以上）在本地就被判定，不需要查询完整库。

**H1 和 H2 都可能是错的。** 如果重校准之后普通压缩就已经够用，那这个课题的缺口就不存在，应该改成实证评测研究。如果区间太宽导致几乎所有图都要升级，那机制就没有价值。**这两种否证结果都是有效的阶段产出**，我会如实报告。

### 1.4 研究边界

必须先把话说清楚，避免过度声称：

- 本项目**只做决策保持，不改进检测精度**。参考检测器本身的误报和漏检，压缩过程只会**忠实地保留**，不会修复。
- 本项目**不声称新的数学定理**。三角不等式和度量球是既有技术。
- 本项目**不使用测试集的缺陷标签来调阈值或选参数**。一旦用了，实验作废。
- 目前**没有真实的边缘设备**，所以延迟结论只基于工作站测量，不外推到产线部署。

## 2. 文献综述 Literature Review

### 2.1 基于记忆库的工业异常检测

PatchCore [1] 确立了这一范式：ImageNet 预训练的 WideResNet-50 提中层特征，局部邻域聚合得到块特征，全训练集的块特征并起来作为记忆库，测试时用最近邻距离打分，并用贪心 coreset 做子采样。它的关键贡献之一是指出：**coreset 子采样到 1% 时，测试时真正被用到的库样本比例从不到 30% 升到接近 95%。** 这说明未压缩的库有大量冗余。

AnomalyDINO [2] 走向另一个极端：完全不训练，冻结 DINOv2，只用 1/4/16 张参考图建库，用「前 1% 最大距离的均值」作为图像分数。它说明冻结特征加小库在少样本下已经很强。

在工业应用侧，记忆库思想被反复改造。Wang 等人 [5] 把它和对比学习结合，用于导管产品的少样本缺陷检测；Jia 和 Chen [6] 用记忆增强的去噪重建做风机叶片损伤检测。中文文献里，张帅和刘美菊 [9] 用偏差减少耦合超球面的方式做工业图像异常检测；赵明明和张二虎 [10] 则关注语义与细节的协同融合。

**小结**：记忆库方法是成熟的，压缩也是标准做法。但上面这些工作报告的都是 AUROC、AP 这类**排序指标**，没有人报告「固定阈值下判决是否改变」。

### 2.2 检索加速与压缩

既然瓶颈在检索，降本的方向主要有两个：把库变小，或者把检索变快。

Li 等人 [4] 的级联块检索是个好例子：通过粗到细的级联筛选，把异常检测和定位压到一毫秒以内，同时保持精度。这类工作说明「分级筛选」在工程上是可行的。

但要注意一个区别：**大部分加速工作优化的目标是「让精度不掉」，而不是「让判决不变」。** 前者是排序层面的，后者是决策层面的。这两件事在 AUROC 上看起来一样，在产线上完全不同。

### 2.3 边缘部署

Shallari 等人 [8] 讨论了视觉异常检测从边缘到雾节点的部署问题，指出实际部署中延迟和带宽是主要约束。EfficientAD [3] 则从模型侧回答同一个问题：用一个小的学生-教师网络代替记忆库检索，在毫秒级延迟下达到很好的精度。

这里有个容易被混淆的点，值得单独提一句：**EfficientAD 这类「小模型」和「小检索库」是两回事。** 前者的参考知识被压进网络权重，测试时内存恒定；后者的内存随训练集增长。本项目研究的是后者，因为它的失效模式更容易被察觉（库变了，分数就变了），也更适合做可审计的保证。

### 2.4 研究空白

把上面几条合起来看，空白就比较清楚了：

1. 已有工作报告排序指标，**不报告固定阈值下的判决一致性**。
2. 已有压缩工作报告精度损失，**不报告「压缩后阈值还准不准」**。
3. 已有加速工作报告延迟，**不把「决策保持」作为一个可审计的契约**。

说白了，大家都在比谁分高，很少有人问：**这个分数在阈值那儿还靠谱吗？** 这就是本项目要补的位置。

## 3. 研究内容与方法 Method

### 3.1 符号与设定

设 `M` 为冻结的完整记忆库，包含 `N` 个 `D` 维的正常块特征。查询块为 `q`，欧氏距离记为 `d`。参考检测器的分数定义为

```
s_M(q) = min_{m ∈ M} d(q, m)          （块的分数）
S_M(x) = max_{q ∈ x} s_M(q)           （图像分数，取最大）
```

判决规则统一为：**当且仅当 `S_M(x) > t` 时报警**，取等号算正常。阈值 `t` 在独立的校准正常图上按名义 5% 图像误报率确定。

### 3.2 压缩与覆盖半径

用贪心 coreset 从 `M` 中选出 `K` 个**观测中心** `c_j`（注意：中心必须真的是库里的点，不能是算出来的平均点）。把所有库向量按最近中心分到 `K` 个单元，然后给每个单元算一个**覆盖半径**

```
r_j = max_{m ∈ C_j} d(m, c_j)
```

边缘侧需要存的，就只有 `K` 个中心加 `K` 个半径。

### 3.3 区间与三角不等式

这是全篇唯一的数学，而且不难。三个量：

```
U(q) = min_j d(q, c_j)                       上界
L(q) = min_j max(0, d(q, c_j) − r_j)         下界
```

**为什么成立？** 两句话：

- **上界**：每个中心本身就在库里。在「只有中心」这个子集里找最近邻，结果只会比在「全部点」里找更差，所以 `s_M ≤ U`。
- **下界**：三角不等式，也就是**绕路不会更近**。中心 `c` 离查询 `q` 有 `d` 那么远，单元里的点都在 `c` 周围 `r` 以内，那单元里任何点到 `q` 至少是 `d − r`。所以 `s_M ≥ d − r`，取所有单元的最小值就是 `L`。

于是 `L(q) ≤ s_M(q) ≤ U(q)`。图像级因为取最大是单调的，区间可以直接传递上去。

### 3.4 四分支判决

```
① U_x ≤ t        → 判「正常」，本地，不查库
② L_x > t         → 判「报警」，本地，不查库     （必须是严格大于）
③ 其他            → 升级查完整库，用它的结果
④ 查不到          → 返回「未解决」，绝不判「正常」
```

第②条一定要写严格大于。因为判据是「严格大于才报警」，当 `L_x` **正好等于** `t` 时，参考检测器的答案其实可能是「正常」。写成 `>=` 就会凭空制造一次不一致，而且不会报任何错。

第④条是本项目在工程上最看重的一条：**把「不知道」当成「正常」，等于漏检。** 这是产线上最不能出的错。

### 3.5 数值可靠性

有两个坑必须处理：

1. **浮点误差会让区间失效。** 我们用「直接相减」而不是 `|a|² + |b|² − 2ab` 展开式来算距离，因为后者在高维下会严重抵消。实测中，展开式曾让 676 个块里有 31 个出现 `L > s`，也就是下界比真值还大——这会产生**假的「已验证报警」**。
2. **半径只能向上取整，下界只能向下取整。** 这样才能保证保守。

但要说清楚：加了保护之后，我们得到的只是**经验上的决策保持**，不是形式化的数值证书。论文里只能写 "empirically decision-preserving"。

### 3.6 版本控制

「保持判决」这句话，没有版本是没有意义的。所以每个产物都带一个版本标识，把**编码器、预处理、库内容哈希、阈值**打包成指纹。一旦对不上，直接返回「未解决」，不猜。

## 4. 实验设计 Experiments

### 4.1 数据与角色划分

主实验用 MSC-AD [7]（铸件表面小缺陷）和 MVTec AD 的三个类别（bottle、tile、screw），后者按 PatchCore [1] 的协议准备。三类分别覆盖物体、纹理和小缺陷。

正常图必须切成**三个互不重叠的角色**：

| 角色 | 用途 | 比例 |
|---|---|---|
| reference-fit | 只用于建记忆库 | 60% |
| development | 只用于开发期决策 | 20% |
| final-calibration | 只用于确定阈值 | 20% |

同一张图不能出现在两个角色里。少样本变体的 1/4/16 张参考图，**只能**从 reference-fit 里抽，另外两个角色的图**另外计数**。

### 4.2 对照与消融

- **完整记忆库**：参考检测器，作为金标准
- **等字节随机压缩库**：最朴素的降本方式
- **等字节贪心压缩库**：PatchCore 式 coreset [1]
- **压缩 + 独立重校准**：检验「简单重校准能不能直接解决问题」
- **全局半径 vs 分单元半径**：本方法的核心消融

### 4.3 指标

| 类别 | 指标 |
|---|---|
| 决策保真 | 与参考检测器的不一致率；拆成「多报」和「漏报」 |
| 真实效果 | 缺陷召回率、正常图误报率（按名义 5% 报） |
| 机制诊断 | 区间宽度分布；`L = 0` 的比例；升级率；未解决率 |
| 资源 | 库字节数；平均延迟与 p95；构造时间 |
| 统计 | 按原图分组的配对 bootstrap 置信区间；5 个随机种子 |

### 4.4 预实验（已完成）

第一周已经在冻结的 WideResNet-50 上跑通了完整管线，得到一个**值得注意的中间结果**：

| 指标 | 实测值 |
|---|---|
| 真实分数 `s_M` 范围 | 0.6637 – 1.2635 |
| 平均区间宽度 | 1.1267 |
| 下界 `L = 0` 的块比例 | 73.1% |
| `L > s_M` 违规数 | 0 |
| `s_M > U` 违规数 | 0 |

两件事同时成立：**区间是正确的（零违规），但区间比信号本身还宽。** 这直接说明 H2 有风险，需要在正式实验里用更大规模的库重新检验。这个自我否证的设计是刻意的。

（另外说明一处已更正的方法学错误：早期版本中用「记忆库自己的块」当查询，导致真实分数恒为 0，`L = 0` 是同义反复。已改为留出查询后重测，数字如上。）

## 6. 预期成果 Expected Outcomes

1. **一套可审计的评测协议**：把「压缩引起的决策不一致」和「检测精度」分开度量。
2. **一个可运行的筛选系统**：带版本控制和「未解决」状态，代码公开。
3. **一条实证边界**：在什么压缩比、什么特征维度、什么光照条件下，报警还能保持。
4. **诚实的负面结论**：如果机制不成立，给出它为什么不成立的具体证据。

**不承诺**：不承诺精度提升，不承诺能耗下降，不承诺产线部署效果。

## 7. 风险与应对 Risks

| 风险 | 应对 |
|---|---|
| 缺口不存在（H1 被否证） | 转为严谨的实证评测研究，报告负面结论 |
| 区间太宽，几乎全部升级（H2 被否证） | 增加层级细化，或降级为「正常侧的廉价证书」 |
| 简单重校准就能解决问题 | 如实报告，把重校准作为最强基线 |
| 没有边缘设备 | 只报告工作站测量，明确标注为模拟 |
| 数据集不可获取 | 用公开数据集替代，绝不使用未授权数据 |
