# 手算区间例子 / Worked Bound Example

**对应 / Corresponds to:** Research Plan Part A14 Immediate Assignment #3
**可执行版本 / Executable version:** `scripts/02_worked_bound_example.py`
**原始输出 / Raw output:** `results/logs/worked_bound_example.json`

要求在 6 个参考向量 + 2 个观测中心的集合上算出 `L(q)`、`s_M(q)`、`U(q)`，
并包含一个阈值相等的 tie 和一个需要升级的 case。

---

## 1. 参考集合与中心 / The reference set and its centers

参考银行 `M`（6 个 2-D 向量）与 2 个**观测**中心（中心必须取自银行）：

| 点 | 坐标 | 最近中心 | `d(m_j, c_j)` |
|---|---|---|---|
| m₁ | (0, 0) | c₁ = (0,0) | 0 |
| m₂ | (2, 0) | c₁ | 2 |
| m₃ | (0, 2) | c₁ | 2 |
| m₄ | (10, 0) | c₂ = (10,0) | 0 |
| m₅ | (12, 0) | c₂ | 2 |
| m₆ | (10, 2) | c₂ | 2 |

单元划分（最近中心）：`C₁ = {m₁,m₂,m₃}`，`C₂ = {m₄,m₅,m₆}`。

半径（单元内最大距离）：
`r₁ = max(0, 2, 2) = 2`，`r₂ = max(0, 2, 2) = 2`。
存储时向上取整为 `2.000002`（数值护栏，见 `numerics_contract.md` §4）。
手算时用 `r = 2` 即可。

阈值 `t = 3`。判决规则：**alarm ⟺ `s_M > t`**，取等号为 NORMAL。

---

## 2. 逐查询计算 / Query-by-query

公式：
```
U(q) = min_j d(q, c_j)
L(q) = min_j max(0, d(q, c_j) − r_j)
s_M(q) = min_{m ∈ M} d(q, m)
```

### Q1 = (1, 1) — 本地判 NORMAL

- `d(q,c₁) = √2 = 1.41421`，`d(q,c₂) = √82 = 9.05539`
- `U = min(1.41421, 9.05539) = 1.41421`
- `L = min(max(0, 1.41421−2), max(0, 9.05539−2)) = min(0, 7.05539) = 0`
- `s_M`：到 m₁/m₂/m₃ 都是 `√2 = 1.41421`（最近），到 m₄ = 9.05539 →
  `s_M = 1.41421`
- 检验：`0 ≤ 1.41421 ≤ 1.41421` ✓
- 判决：`U = 1.41421 ≤ t = 3` → **NORMAL，本地判定，不升级**。✓ 与参考一致。

### Q2 = (11, 0) — 本地判 NORMAL

- `d(q,c₁) = 11`，`d(q,c₂) = 1`
- `U = 1`
- `L = min(max(0, 11−2), max(0, 1−2)) = min(9, 0) = 0`
- `s_M`：m₅=(12,0) 距离 1，m₄=(10,0) 距离 1 → `s_M = 1`
- 检验：`0 ≤ 1 ≤ 1` ✓
- 判决：`U = 1 ≤ 3` → **NORMAL，本地**。✓

### Q3 = (30, 0) — 本地判 ALARM

- `d(q,c₁) = 30`，`d(q,c₂) = 20`
- `U = 20`
- `L = min(max(0, 30−2), max(0, 20−2)) = min(28, 18) = 18`
- `s_M`：m₅=(12,0) 距离 18 → `s_M = 18`
- 检验：`18 ≤ 18 ≤ 20` ✓（这里 `L` 恰好紧）
- 判决：`L = 18 > 3` → **ALARM，本地判定，不升级**。✓
- **注意这个例子的意义**：区间宽度是 2，但完全落在阈值同一侧，
  所以不需要精确分数。这就是"远离阈值的图不需要准确分数，只需要足够紧的区间"。

### Q4 = (5, 0) — **阈值相等的 tie → 必须升级**

- `d(q,c₁) = 5`，`d(q,c₂) = 5`（正好在单元边界上）
- `U = 5`
- `L = min(max(0, 5−2), max(0, 5−2)) = min(3, 3) = 3`
- `s_M`：m₂=(2,0) 距离 3，m₄=(10,0) 距离 5 → `s_M = 3`
- 检验：`3 ≤ 3 ≤ 5` ✓
- 参考判决：`s_M = 3 = t`，判据是**严格大于**，所以 `3 > 3` 为假
  → **参考判决 = NORMAL**
- 走 screening 规则：`U = 5 > 3`，`L = 3 > 3` 为假 → **不满足分支 2**
  → 落到分支 3：**升级**，全银行查询返回 NORMAL。
- **如果规则写成 `L >= t`**：分支 2 会触发，直接判 ALARM，
  而参考判决是 NORMAL → **一次静默的不一致**。

这就是为什么 `screen_image` 里必须写 `if lower > threshold`。
数值上，护栏让 `L = 2.999995 < 3`，所以即使有人误写 `>=`，
在这个具体例子上护栏恰好挡住了一次错误——但**不能依赖这一点**，
在别的数上护栏可能不够。规则本身必须是严格的。

### Q5 = (6.5, 0) — 区间跨阈值 → 升级，参考判 ALARM

- `d(q,c₁) = 6.5`，`d(q,c₂) = 3.5`
- `U = 3.5`
- `L = min(max(0, 6.5−2), max(0, 3.5−2)) = min(4.5, 1.5) = 1.5`
- `s_M`：m₄=(10,0) 距离 3.5，m₂=(2,0) 距离 4.5 → `s_M = 3.5`
- 检验：`1.5 ≤ 3.5 ≤ 3.5` ✓
- `U = 3.5 > 3` 且 `L = 1.5 > 3` 为假 → **升级**
- 全银行返回 `s_M = 3.5 > 3` → **ALARM**

这个例子说明：升不升级取决于**区间是否跨过阈值**，不取决于图是否异常。
`U` 只比 `t` 高 0.5，但因为 `L` 远低于 `t`，必须付一次全银行查询。

## 5. 三角不等式的白话解释 / The triangle inequality, in plain language

三角不等式说的是：**绕路不会更近**。
从 A 到 B 再到 C 的总路程，不可能比直接从 A 到 C 更短。

在这个项目里它被用在两个方向：

**方向一（求下界，用于判 ALARM 和剪枝）。**
我知道中心 `c` 到查询 `q` 的距离是 8，我也知道单元里所有点都在 `c` 周围半径 2 以内。
那么单元里**任何**点到 `q` 的距离至少是 `8 − 2 = 6`——
因为它必须先"靠近 c"，然后再从 c 走到 q，绕了路。
所以只要 6 已经比当前已知的最好结果大，整个单元就可以扔掉。
**注意这个论证只给出"至少多远"，永远给不出"至多多远"。**
这就是为什么只有下界能用来剪枝：只有"最乐观也不可能更近"才允许丢弃。

**方向二（求上界，用于判 NORMAL）。**
因为每个中心**本身就在银行里**，所以"到中心的距离"就是"到银行里某个点的距离"。
银行里的最小值不可能比这个更大。这就是 `U`。

**为什么下界通常很松、上界通常较紧？**
`L` 用的是单元内**最远**那个点到中心的距离作为半径。
只要单元里有一个离群点，半径就被它撑大，`d(q,c) − r` 就被压到 0。
而 `U` 只用到中心本身，不需要半径。这就是 Phase 0 观测到
676 个 patch 的 `L` 全部为 0 的原因，也是 `open_questions.md` 里 Q5 的来源。

## 6. 空单元的陷阱 / The empty-cell trap

如果某个单元 `C_j` 是空的，而给它 `r_j = 0`，那么该项变成 `max(0, d(q,c_j)) = d(q,c_j)`。
但 `c_j ∈ M`，所以 `d(q,c_j) ≥ s_M(q)`——这是一个**上界**，
把它放进 `min` 会让 `L` 有可能**超过** `s_M`，证明失效。

本仓库因此让 `build_coverage_index` 在遇到空单元时**抛异常**，
而不是悄悄用半径 0。代码里也写了这个理由。
（当中心取自银行本身时单元必然非空，所以这只是防御性检查。）

## 7. 数值护栏的作用 / What the guard does here

| | 半径 |
|---|---|
| 加护栏 | `[2.000001907, 2.000001907]` |
| 不加护栏 | `[2.0, 2.0]` |

在这个条件良好的整数例子上护栏**什么都没改变**。
它存在的理由是：在真实的 float32 特征上，半径是对约 `10³–10⁵` 个数取最大，
如果 `r_j` 向下舍入，`L` 就会偏大，证书就不安全。
Phase 0 确实抓到了这个方向的真实故障（见 `numerics_contract.md` §3.1）。

不过要诚实：**护栏只是经验允许量，不是证明的误差界。**
因此本项目一律用 "empirically decision-preserving"，不用 "formally certified"。
