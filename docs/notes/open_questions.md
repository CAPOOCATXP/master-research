## Q1 — 阈值分位数的确切约定 / Exact quantile convention for the threshold

**背景.** 计划 A7 要求：报告 nominal 5% 图像误报目标下的阈值，并报告
"the exact empirical quantile convention"。

**问题.** bottle 的 `final_calibration` 只有 42 张正常图（60/20/20 划分的 20%）。
名义 5% 意味着阈值之上应有约 2.1 张图。在这么小的样本上，
`lower` / `higher` / `linear` / `midpoint` 等插值约定会给出**不同**的阈值，
进而改变**所有**不一致计数——而不一致计数正是整个项目的核心测量量。

**我倾向.** 在预注册文件里固定 `linear` 插值并同时报告 `lower`/`higher` 的
敏感性带；如果两种约定的不一致率差异超过 1 个百分点，就把校准集扩大到
30% 并相应缩小 `reference_fit`。

**影响.** 决定 Phase 3 的预注册内容，以及角色划分比例是否要改。

## Q2 — 压缩银行重新校准时的数据泄漏 / Recalibration leakage

**背景.** 计划 A7 要求两件事同时做：
(i) 冻结参考检测器的 `t`，测决策保持；
(ii) 单独重新校准**每个**压缩检测器，看简单重校准能否消除问题。

**问题.** (ii) 的重新校准必须在正常图上取分位数。如果用的是同一批
`final_calibration` 图，那么 (i) 和 (ii) 就在同一批数据上做了两个不同的实验。
这算不算泄漏？严格说：**不算**——因为 (ii) 是在测"如果允许重新校准会怎样"，
本来就应该给它同等的数据预算。但如果要用 (ii) 的结论去支持
"重校准解决了问题"，那就需要用**没被 (i) 用过**的正常图来验证。

**我倾向.** 再切出第四个角色 `recalibration_validation`（约占正常图的 10%），
把 (i) 的 `t` 和 (ii) 的重校准阈值分开。代价是 `reference_fit` 变小。

**影响.** 决定要不要引入第四个数据角色，以及 A7 的两组对比能否公平比较。

## Q3 — 区间宽度到底是维度的本质还是银行太小的假象 / Is the interval width intrinsic?

**背景.** 这是我认为**最该先测**的问题。Phase 0 实测：
`N = 676`（单张图的 patch 数）、`K = 68` 个中心、`D = 1536` 维时，
**676 个 patch 的下界全部为 0**（`touching_zero_lower_count: 676`），
平均区间宽度 0.86。

**问题.** 这意味着 screening 会 100% 升级，机制完全无效。
但这可能是我的银行太小造成的假象：单张图只有 676 个 patch，
而真实的 MVTec 银行是 200+ 张图，`N ≈ 1.4 × 10^5`。
在 `N` 和 `K` 都大两个数量级时，`r_j` 会相对变小吗？

我的直觉是**会变糟而不是变好**：高维空间中球体积集中在壳层，
单元内的点会离中心越来越远，`r_j` 相对 `d(q,c_j)` 会越来越大。
但我没有计算，也不该靠直觉。

**我倾向.** 在 Phase 3 之前先做一个便宜的合成实验：
固定 `D ∈ {32, 256, 1536}`，扫 `N ∈ {10^3, 10^4, 10^5}` 与 `K/N ∈ {1%, 10%}`，
记录 `L=0` 的比例与平均区间宽度。这不需要数据，只需要摘要里就能跑。
如果 `L=0` 的比例在所有配置下都接近 1，**C2 的机制前提就不成立**，
应该在 Gate 3 之前就 STOP 或改写问题。

**影响.** 这是"机制是否可能有效"的前置判断，直接决定 C2/C3 是否还值得做。
计划 A11 已经列出 "wide bounds causing almost universal escalation" 为首要风险之一。

## Q4 — 公平比较的基线该是什么 / What is the fair timing baseline?

**背景.** Phase 0 实测：`N = 676`、`K = 68`、`D = 1536`、`P = 676` 时，
screening 扫描 **18.8 ms**，完整银行扫描 **8.5 ms**——screening **更慢**。

**原因（已定位，不是 bug）：**
- 完整银行路径：一次 BLAS matmul 排序，只对 4 个候选做精确直接相减 → 快。
- screening 路径：`L` 在所有单元上取 min，所以**必须**对**每个**中心算精确距离，
  不能用"排序 + 少量精化"的技巧 → 内存受限，慢。
- 理论 FLOP 比是 `N/K ≈ 9.9×`，太小，不足以补偿上面的差异。

**问题.** 计划 A10 要求的 break-even 分析应该在哪一层做？
(a) **同样精确**的实现对比（即也给完整银行逐点直接相减）——
    这样 FLOP 比才是唯一变量，但会让完整银行看起来很慢，有失公平。
(b) **各自最快的实现**对比——更接近部署现实，但筛掉的是我的实现质量，
    不是算法的性质。
(c) 两者都报，并明确说明差异来自实现而非算法。

**我倾向 (c)**，并在 Phase 6 加一条"实现等价性检查"：
证明两个路径在相同精度约束下必须做的工作量分别是 `O(PKD)` 和 `O(PND)`。

**影响.** 决定 C3 的"资源前沿"怎么定义和怎么呈现。

## Q5 — 如果 `L` 恒为 0，`U` 单独是否还够？/ Does only `U` matter?

**背景.** 见 Q3：Phase 0 里 `L` 恒为 0。
如果这在真实配置下也成立，screening 规则就退化成：

```
if U_x <= t:  return NORMAL
else:         escalate
```

也就是说**只有上界在用**，区间跨阈值的判 ALARM 分支永远不会触发。

**问题.** 那么：
1. 计划 A10 里 "global radius vs per-cell radii" 的消融还有意义吗？
   如果 `L` 恒为 0，per-cell 与 global 的差别只体现在 `U` 上，
   而 `U` 根本不依赖半径——它只依赖中心到查询的距离！
   这意味着**半径的存在对判决毫无影响**，整个"覆盖半径"机制就没有作用了。
2. 如果是这样，C2 的贡献就从"区间 screening"退化为
   "分层最近中心预筛 + 全局半径做快速 NORMAL 判定"，这是一个弱得多的说法。

**我倾向.** 这是一个**可能推翻 C2 表述**的观察。
在 Phase 3 的合成实验里（Q3）同时记录 `L > t` 分支的触发率。
如果它恒为 0，就应该把方法描述改为：
"per-cell **cover radii** 提供一个廉价的 NORMAL 证书；ALARM 一侧需要升级"，
并诚实地说明降级背后的原因，而不是继续声称一个双向区间机制。

**影响.** 直接改写 C2 的表述。这也是我在 `phase1_reading_notes.md` §7
里写下"假设变更"的原因。
